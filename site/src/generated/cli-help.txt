=== archon
usage: archon [--workspace <state-dir> | --server <url>] <mission|formation|gate|end|limit|tool|agent|run|peer> <command> [arguments]
       archon [--server <url>] version

Archon chains agents and gates. Name the state directory with --workspace to
work on its files offline, or a daemon with --server; there is no default.
Runtime commands (mission run, formation run, run, gate approve|reject) go
through --server.

  mission    missions: the reusable unit
  formation  steps: the agents that do the work
  gate       checks between steps, and human verdicts
  end        End nodes, which end a path on purpose
  limit      Limit cards, which cap a step or the whole mission
  tool       Tool nodes
  agent      role cards
  run        runs, through the daemon
  peer       a peer formation's conversation, for its seats

Run "archon <noun> -h" for its commands and "archon <noun> <command> -h" for a command's flags.
=== mission
usage: archon mission <command> [arguments]

A mission is the reusable unit: one .mission.toml file whose Input card starts each run.

  delete <mission>                         remove the whole mission and its layout; run history remains
  new <slug>                               create an empty mission
  list                                     list the missions
  inspect <mission> [<input>]              print the whole mission, or an Input card and the steps it reaches
  notes <mission>                          print the mission's note threads
  note <mission>                           add to a note thread
  validate <mission>                       list every finding that would stop a run, naming each node by title and ID
  arrange <mission>                        replace saved canvas positions with compact reading rows
  create <mission>                         add the Input card to a mission that has none
  update <mission> [<input>]               change the Input card
  input <mission> [<name>]                 list the inputs a run supplies, or with a name declare, change or --delete that input
  output <mission> [<name>]                list the outputs a successful run promises, or with a name declare, change or --delete that output
  wire <mission> [<input>] <to-node:port>  wire the Input card to a step
  run <mission>                            start a run

<input> may be left out when the mission has one Input card.

Run "archon mission <command> -h" for a command's arguments and flags.

=== formation
usage: archon formation <command> [arguments]

A formation is a step: the team of agents that does it, solo, peer or orchestrated.

--- assign
usage: archon formation assign <mission> <formation> --slot <slot> (--character <id> | --harness <claude-code|openai-codex|pi> --effort <effort>) [--model <model>] [--role <persona>] [--json]
Staff a slot. A slot owns its harness, model and effort; --role adds optional role text, and a slot without one is a vanilla agent. --character stamps a saved character's role, harness, model and effort, each replaced by its own flag when given; the slot keeps no link to it.
Choose the effort by the policy: low for errands (verifier, scout); medium for making things (builder, debugger, operator); xhigh for architecture and review (reviewer, judge, architect, designer, planner, orchestrator); max for consequential reviews, chosen by hand. claude-code takes low, medium, high, xhigh, max; openai-codex takes low, medium, high, xhigh, max, ultra; pi takes low, medium, high, xhigh, max; a known Codex model may take fewer.
A blank --model means the harness default model. Known models: claude-code runs opus, sonnet, haiku, fable; pi runs anthropic/claude-opus-5-5, anthropic/claude-sonnet-5-5, anthropic/claude-haiku-5-5, anthropic/claude-fable-5-1. Other model names are accepted; the harness decides.
  -character string
        saved character (agent characters) to staff the slot as: its role, harness, model and effort, each replaced by its own flag when given
  -effort string
        reasoning effort; policy: low for errands (verifier, scout); medium for making things (builder, debugger, operator); xhigh for architecture and review (reviewer, judge, architect, designer, planner, orchestrator); max for consequential reviews, chosen by hand
  -harness string
        harness the seat runs: claude-code or openai-codex or pi
  -json
        write JSON
  -model string
        model the seat runs; blank means the harness default model
  -role string
        optional role (persona id); omit it for a vanilla agent
  -slot string
        slot id
  -updated-by string
        update actor (default "agent:archon")

=== limit
usage: archon limit <command> [arguments]

A Limit card caps the step it covers, or the whole mission when it covers the Input card. With --when-spent fail the run fails at the limit; otherwise it blocks until run resume --grant, or, with --when-spent best, picks the step's best attempt and goes on.

  create <mission>          add a Limit card
  update <mission> <limit>  change a Limit card
  delete <mission> <limit>  remove a Limit card

Run "archon limit <command> -h" for a command's arguments and flags.
--- create
usage: archon limit create <mission> --target <step|input> [--rounds n] [--time 30m] [--warn 5m] [--tokens n] [--when-spent stop|best|fail] [--title text] [--x n] [--y n] [--json]
Add a Limit card. --when-spent fail ends the run as failed, keeping attempt evidence. By default the run blocks; run resume --grant gives one more round, or the card's time or tokens again. With --when-spent best a step's card picks the best attempt its gate judged and goes on through the gate's pass route; the step needs one judge or human gate that only it feeds and whose fail returns to it. Tokens are approximate: input not read from the cache, cache writes included, plus output, subagents included.

flags:
  -json
        write JSON
  -rounds string
        how many times the step may run, send-backs included (a peer step: its journal messages), or how many steps the whole mission may run
  -target string
        the step it covers by ID or title, or input (the Input card) for the whole mission
  -time string
        how long the step, or every step of the mission, may work in whole seconds, such as 45s, 30m or 1h30m; waiting on a human gate does not count
  -title string
        Limit card title (default Limit)
  -tokens string
        how many tokens the step, or every step of the mission, may spend, approximately: input not read from the cache, cache writes included, plus output, subagents included
  -updated-by string
        update actor (default "agent:archon")
  -warn string
        how much time is left when the covered seats are warned, such as 5m
  -when-spent string
        what the spent card does: fail ends the run as failed; stop (the default) blocks the run for a grant; best picks the best attempt the step's gate judged and goes on through its pass route
  -x int
        layout x coordinate
  -y int
        layout y coordinate

=== run
usage: archon run <command> [arguments]

A run is one start of a mission or a single step. Read and drive runs with --server.

  list                    list runs, or one mission's, newest first: one line per run with its ID, mission, status, Bead, start and last change
  status <runId>          print a run's status
  storage <runId>         inventory run evidence and its ordinary budgets
  attempts <runId>        list each attempt with its status, outputs and gate verdicts; add --files to list attempt files; JSON includes complete evidence
  logs <runId>            print a run's projection
  follow <runId>          print the run as it changes until it is final; exits 7 when it ended picked
  wait <runId>            block until the run needs you, ends or changes; exits 0 when final, 7 when final as picked, 3 needs you, 4 changed
  gates <runId>           list a run's waiting gates and the seats they asked
  seats <runId>           list a run's seats, their session names and what each waits on
  resume <runId>          resume a blocked run
  abort <runId>           stop a run
  ask <runId> [question]  summarize what a run has done, offline

Run "archon run <command> -h" for a command's arguments and flags.
--- list
usage: archon run list [--mission <mission>] [--json]
List runs, or one mission's, newest first: one line per run with its ID, mission, status, Bead, start and last change. --json prints each run's full projection.

flags:
  -json
        write JSON
  -mission string
        list only this mission's runs
--- status
usage: archon run status <runId> [--json]
Print a run's status. A final run adds outcome, reason (when recorded, with a code when present) and endedBy (when known) lines. A run that succeeded or was picked lists its mission outputs, one output line each with name, kind and value; pass a value to the next mission's --input. A picked run's outputs that came through a pick add picked and finding lines: failed work, not a pass.

flags:
  -json
        write JSON
--- storage
usage: archon run storage <runId> [--archive | --unarchive | --dispose] [--json]
Inventory run evidence and its ordinary budgets. Archive explicitly retains large evidence outside those budgets; resume a blocked run separately. Dispose removes final, unreferenced evidence and preserves compact history. Legacy runs are inventory-only unless explicitly disposed.

flags:
  -archive
        retain this run outside the ordinary evidence budget; resume separately
  -dispose
        remove final run evidence, preserving compact history
  -json
        write JSON
  -unarchive
        return this run to ordinary evidence retention

  -node string

--- resume
usage: archon run resume <runId> [--mode reattach|redispatch] [--grant | --pick-best] [--take-fail] [--reason text] [--actor actor] [--json]
Resume a blocked run. --grant gives a step its spent Limit card stopped one more round, or the card's time or tokens again. --pick-best picks the best attempt the step's gate judged and goes on through its pass route instead, whatever the card's whenSpent. At a judge verdict Archon rejected, resume asks the judge again and --take-fail fails the gate instead.

flags:
  -actor string
        resume actor (default "agent:archon")
  -grant
        give the step a spent Limit card stopped one more allowance (one more round, or the card's time or tokens again); the ledger records the grant and who gave it
  -json
        write JSON
  -mode string
        resume mode (default "reattach")
  -pick-best
        pick the best attempt the stopped step's gate judged and go on through the gate's pass route, whatever the card's whenSpent; not with --grant
  -reason string
        resume reason
  -take-fail
        settle a gate blocked on a judge verdict Archon rejected as a fail: the gate fails and routes, and the judge is not asked again; without it, resume asks the judge again
