A complete example

A drafting step whose file output is reviewed by a judge and then the operator, sent back on failure, capped at three drafts with the best one picked, and promised as the mission's output. It validates as written.

Top level

KeyValue
schema1.
idThe mission's stable identity. New missions get msn_ followed by a ULID; runs belong to a mission by this ID, not its slug.
slugThe name commands use; matches the file name.
titleThe display name.
revThe revision, raised by every saved edit. Edits and run starts can require the current revision.
updatedBy, updatedAtWritten by Archon.

[[inputCard]]

Exactly one per file. A file with several loads and stays editable, but validation reports several_input_cards and no run starts.

KeyValue
id, title, goalIdentity, display name and the mission goal every seat sees as context.
inputsArray of { name, kind, required, description }. kind is text (default), file or folder.
outputsArray of { name, kind, required, description, from }; from is "<step-id>:<port-id>" of a port of the same kind.
inputHintDescribes the implicit brief input of a mission that declares none.
filesAbsolute paths of reference files.
humanChannelsession to route human gates to the asking seats; absent means notify.

Its one output port is out, as in from = "inp_draft:out".

[[formation]]

KeyValue
id, titleIdentity and display name.
typesolo, peer or orchestrated.
[formation.brief]goal (the brief, with {input} references), beadId, files and links.
[[formation.input]]id, label. Each input port takes one feed; a step waits for all of them.
[[formation.output]]id, label, optional kind (file or folder; absent means text).
[[formation.slot]]id, label, harness, model, effort, optional agentId (the role) and controller. In an orchestrated step exactly one slot has controller = true.

Slot IDs are unique across the whole mission (a seat's session is named after its run and slot) and are a letter or digit followed by up to 63 letters, digits, underscores or hyphens.

[[gate]]

KeyValue
id, title, criterionIdentity, display name and what the gate checks.
kindsAny of "code", "formation", "human".
check, checkVersion, checkValueFor the code kind: output_contains or output_absent, version 1, and the text.
filesReference files such as a rubric.

Ports: in, pass, fail, judge. A judge chain is two or more connections through judge: out from the gate to the first judge, and from the last judge back to the gate.

[[end]] and [[limit]]

TableKeys
[[end]]id, title, outcome (done or rejected). One port: in.
[[limit]]id, title, target (a step ID, or the Input card's ID for the whole mission), rounds, seconds, warnSeconds, tokens, whenSpent (best or fail; absent means stop).

[[connection]]

id, from and to, each endpoint "<node-id>:<port-id>". Wires run from an output (out, a step output, pass, fail) to an input (a step input, a gate's in, an End's in); judge wiring uses judge on both ends.

Tool nodes

A Tool node runs a registered host profile on its input. This source registers one, json.normalize version 1, which normalizes a JSON report. Create Tools with archon tool create, which validates the profile and its parameters, rather than by hand.

The notes file

.archon/notes/<slug>.notes.toml is schema 2: missionId, rev, and one [[entry]] per note entry with id, target (mission or a node ID), author (human:<name> or agent:<name>), createdAt, optional edit time, and text.

schema = 2 missionId = "msn_draft_review" rev = 1 [[entry]] id = "nte_intent" target = "mission" author = "human:ui" createdAt = "2026-11-01T09:00:00Z" text = "Drafts should read like our handbook, not like marketing."

Layout

.archon/layout/<slug>.layout.toml holds card positions ([[node]] with id, x, y) and wire lanes. It is separate so validation never touches positions; mission arrange rewrites it.
