Delivery

delivery.mission.toml with its notes in delivery.notes.toml. It takes a change from plan to reviewed delivery in a repository.

StepStaffing
Planplanner on Claude Code at xhigh
Beadsvanilla Claude Code at medium
Beads reviewer (judge)judge on Claude Code at xhigh
Executionorchestrator controller on Claude Code at xhigh; three builder workers on Codex at medium
Final reviewreviewer on Codex with model gpt-6-astra at max, a consequential review

A run supplies one input, change, which every brief references as {change}. The target repository is the run's --cwd and the owning Bead its --bead.

What it needs

  • Claude Code and Codex, signed in, and the Codex model the Final review slot names (or restaff it).
  • Beads (bd) in the target repository, and the shared skills its briefs name. Archon bundles neither.
  • A real change to deliver. Lab can rehearse its routing first (Lab quickstart).
archon --server "$ARCHON_SERVER" mission run delivery \ --cwd /absolute/path/to/your/repository \ --input-file change=/absolute/path/to/change.md \ --bead your-project-123 --json

Operations proof

operations-proof.mission.toml is a historical proving mission from 2026-09-06: a producer writes an operations guide, an independent reviewer checks it against the source, an integrator folds in corrections, and the run ends at a real operator gate. Its briefs target that one task. Keep it as a pattern for producer, reviewer and human sign-off; adapt the briefs before running it.

More patterns

  • The smallest mission that validates: one step and an End.
  • A reviewed step, built command by command.
  • Draft and review: a file output, judge plus human gate, pushback, best-of-three and a promised output.
  • Fan out and join: parallel reviewers merged by a lead.
