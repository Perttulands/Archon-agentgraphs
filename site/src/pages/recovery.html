Read the block

Start from fresh status: status, final, resumeAllowed and resumePolicy. The problems route lists every block and error with the nodes it names.

Commands on this page are for bash or zsh and need jq. Take the run ID from run list or the command that started it; never guess one.

export ARCHON_SERVER=http://127.0.0.1:8091 # your daemon RUN=run_... # the blocked run, from: archon --server "$ARCHON_SERVER" run list archon --server "$ARCHON_SERVER" run status "$RUN" curl --silent "$ARCHON_SERVER/api/runs/$RUN/evidence/problems" | jq .data.problems

Resume

archon --server "$ARCHON_SERVER" run resume "$RUN" --reason "Recovery evidence inspected" archon --server "$ARCHON_SERVER" run resume "$RUN" --mode redispatch --reason "Seat lost; run the step again"

A plain resume (--mode reattach) runs whatever is still owed and reattaches each open dispatch the block names. It never re-delivers an input a gate already evaluated and never invents a missing completion. --mode redispatch abandons the open dispatches and runs those steps again as new attempts, each one more round for a Limit card. Gates still waiting keep waiting through a resume, and a verdict given while the run was blocked is routed by it.

409 Conflict

A 409 means your view is stale. Read fresh status and use the current requestedSeq. human gate request is no longer pending means someone else decided first or the gate has evaluated newer input. coordinator is executing means the run's last command is still settling: retry after a few seconds.

Restarting the daemon

Restart with the same state directory and configuration. Abort runs first only if you mean to end their seats.

  • On SIGTERM the daemon fences new commands and dispatch, gives active turns five seconds, then detaches from its seats without ending them. Open dispatches stay in a resumable block; waiting human requests stay answerable.
  • On startup, before listening, it scans non-final runs, recovers completed native turns where it can, and records a block naming anything unresolved. It never adopts or cleans up old seats, except seats kept on call for a human gate, which it verifies and keeps managing.
  • A run that only waits on gates survives the restart waiting, with each request's original sequence. A run between steps is blocked (coordinator restarted between steps; resume to continue).

After the restart: run list, then run status for each open run, and resume what is blocked.

Recovering from a chosen transcript

When a turn completed but the daemon could not prove it, you can name the evidence explicitly. All three flags go together, with absolute paths; the daemon checks the original brief's digest, pointer, cwd, session, model, effort and completed turn before continuing.

# Start archond with the same flags it always uses, plus these three: archond --executor tmux --state-dir "$ARCHON_STATE" --listen 127.0.0.1:8091 \ --socket "$ARCHON_SOCKET" --tmux-bin "$(command -v tmux)" \ --claude-transcripts "$HOME/.claude/projects" --codex-transcripts "$HOME/.codex/sessions" \ --resume-run "$RUN" \ --completed-transcript /abs/path/to/native-transcript.jsonl \ --completed-brief "$ARCHON_STATE/briefs/original-brief-file"

Seats and cleanup

Check every seat_cleanup outcome in a run's events. A success does not erase a cleanup failure.

OutcomeMeans
endedThe runtime ended the seat.
kept_on_callLeft running for a session-channel human gate.
left_shutdownShutdown detached from a working seat; the restarted daemon reattaches, and the step's next attempt or the run's end ends it.
goneA kept seat had already disappeared.
left_socket_changedThe tmux server was replaced, so the original seat could not be proven and was left alone.
left_cleanup_failedEnding the seat failed. Inspect it on the host.

A seat that waits a minute on something Archon cannot end records a seat_state: seat_not_ready, waiting_for_idle_input, brief_not_taken, turn_ended_without_sentinel or background_work_pending. run seats shows it as waiting. Find the pane with run seats (its sessionName) and tmux -S <socket> list-panes -a.

Evidence and storage

Archon keeps compact history separately from temporary files. History, frozen definitions, verdicts and briefs stay; working files expire.

  • While a run executes, its declared output copies share a 32 MiB capture budget and 4,096 entries. A copy that would exceed it blocks with output_not_kept instead of partly keeping anything.
  • Once a run is final, its artifact directory is compacted: declared snapshots first, then small Markdown, text and JSON reports (up to 256 KiB each), within the per-run budget.
  • Completed ordinary evidence shares a 256 MiB pool; the oldest expires first. Non-final runs, and runs they reference, are protected.
  • Archon never cleans the project's cwd, native harness transcripts or files reached through symlinks.
archon --server "$ARCHON_SERVER" run storage "$RUN" # size, policy, retention, protected references archon --server "$ARCHON_SERVER" run storage "$RUN" --archive # keep large evidence outside the ordinary budget archon --server "$ARCHON_SERVER" run storage "$RUN" --unarchive archon --server "$ARCHON_SERVER" run storage "$RUN" --dispose # remove a final run's artifact files, keep its history

Archiving can also unblock a pending output copy before run resume. Archive cannot restore files that already expired. Export anything that must outlive this evidence into its own project.
