Release or source

The download on the releases page is {{release.tag}}, which predates missions, Limit cards, End nodes, run wait and Pi (what differs). To follow these docs, build from source; the archive you build installs exactly the same way.

Build from source

The build script rebuilds the cockpit with npm ci and npm run build, then compiles both commands with CGO disabled. It builds both architectures unless you pick one.

git clone https://github.com/Perttulands/Archon-agentgraphs.git archon cd archon ./scripts/build-release.sh --out "$PWD/dist" --arch amd64

The script refuses uncommitted or untracked source; --allow-dirty builds anyway and stamps the commit -dirty. Keep the output in dist/, which Git ignores, so the next build after a git pull is not refused for untracked files. The output is an archive per architecture and a SHA256SUMS file. Install it from that directory:

cd dist sha256sum --check SHA256SUMS tar -xzf archon-{{version}}-linux-amd64.tar.gz cd archon-{{version}}-linux-amd64 ./install.sh --prefix "$HOME/.local"

The archive name carries the VERSION file's number, still {{version}}; archon --version prints the commit that tells this build apart (Releases and source).

Just the two commands

For development you can build the commands without an archive. A plain build reports its version as dev, and a daemon built this way has no bundled cockpit: pass --ui-dir pointing at a built dashboard/dist, or it serves only the API and answers 404 at /.

export ARCHON_BIN="$HOME/archon-dev/bin" # any directory outside the checkout mkdir -p "$ARCHON_BIN" (cd src && go build -o "$ARCHON_BIN/archon" ./cmd/archon \ && go build -o "$ARCHON_BIN/archond" ./cmd/archond) (cd dashboard && npm ci && npm run build) export PATH="$ARCHON_BIN:$PATH"

Install an archive

For a downloaded archive, work in the directory holding it and SHA256SUMS. Verify the checksum, unpack, and run the bundled installer. It defaults to $HOME/.local; --prefix /absolute/path picks another location.

sha256sum --ignore-missing --check SHA256SUMS tar -xzf archon-{{version}}-linux-amd64.tar.gz cd archon-{{version}}-linux-amd64 ./install.sh --prefix "$HOME/.local" export PATH="$HOME/.local/bin:$PATH" archon --version archond --version

The installer checks the platform and the archive's own manifest before it changes anything. Keep development builds out of <prefix>/bin: the installer refuses to replace command paths it does not manage.

The installed layout

bin/archon -> ../lib/archon/current/bin/archon bin/archond -> ../lib/archon/current/bin/archond lib/archon/current -> releases/-- lib/archon/releases/--/ bin/ archon, archond share/archon/ ui/ the cockpit, found by archond automatically examples/ delivery and operations-proof missions docs/ PRODUCT, CONTRACT, DESIGN, ADRs, OpenAPI skills/archon/ the agent skill

Later pages use ARCHON_SHARE for <prefix>/lib/archon/current/share/archon.

Upgrades

Installing a newer archive adds a release directory and switches the current link atomically. Older releases stay on disk. A running daemon keeps its loaded binary until you restart it; restart it with the same --state-dir to keep missions and history, and read Restarting the daemon first if runs are active.

The installer refuses to replace command paths or a current link it does not manage, and refuses a changed installation that claims the same release identity.

Keep state outside the install

Runtime state (missions, notes, layouts, run ledgers and artifacts) lives in a state directory you choose with archond --state-dir and archon --workspace. Keep it outside the install prefix and outside any source checkout, so replacing a release never touches it. A common choice:

export ARCHON_STATE="${XDG_DATA_HOME:-$HOME/.local/share}/archon/state" umask 077 mkdir -p "$ARCHON_STATE"

Release packaging, the archive layout and publication are documented in docs/releasing.md.
