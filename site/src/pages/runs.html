Start a run

Commands on this page are for bash or zsh and need jq. Take step, slot, gate and run IDs from the JSON a command returns (formation list "$M", run status "$RUN" --json); never guess one.

export ARCHON_SERVER=http://127.0.0.1:8091 # your daemon M=review # the mission slug WORK=fmn_... # a step ID from: archon --server "$ARCHON_SERVER" formation list "$M" archon --server "$ARCHON_SERVER" mission input "$M" # what a run supplies START=$(archon --server "$ARCHON_SERVER" mission run "$M" \ --input change="Add CSV export to the report page" \ --input-file spec=/abs/spec.md \ --cwd /abs/path/to/project \ --context-path /abs/prior-art \ --bead proj-123 \ --actor "agent:my-session" \ --json) RUN=$(jq -er .data.runId <<<"$START")
--input name=value, --input-file name=path

One per input, repeated. --input-file sends a local UTF-8 file's text. A file or folder input takes the absolute path of something that exists on the daemon's host. A mission without declared inputs takes --input brief=….

--cwd

An existing absolute directory every seat works in. Omit it and the daemon creates a private workspace under <state-dir>/workspaces/<run> (or --run-workspace-root). Workspaces stay after the run ends.

--context-path

Absolute files or directories every seat must inspect as prior art. Frozen as paths, not contents; reference, not permission to edit.

--bead

The Beads issue the run belongs to. Briefs can reference it as {bead}.

--actor

Who is driving, recorded as the run's startedBy. Defaults to ARCHON_DRIVER, then agent:archon.

Admission checks everything at once and refuses with every finding listed (HTTP 422, RUN_ADMISSION_FAILED); no run is recorded. If the start's answer is lost, check run list --mission "$M" before starting again: the run continues even if the client disconnected.

Drive it with run wait

Start run wait right after the launch, and again after every answer. It blocks until something needs the driver, prints one paragraph written for an agent, and exits with a code that says what happened.

archon --server "$ARCHON_SERVER" run wait "$RUN" --until needs-you
ExitMeansDo
3The run needs youFollow the paragraph: it names the gate, its criterion and input and where each verdict leads, with the exact gate approve and gate reject commands; or the run resume or run abort a block needs. Then wait again.
0The run is finalRead how it ended: status, where it stopped, the reason and who ended it.
7Final as pickedIts outputs are failed work a pick carried on. Do not chain them as a success.
4Something changed (any-change)Read the listed events and wait again.
5--timeout passed firstWait again with the same command.
6The daemon stayed unreachable for --reconnect (default one minute)Run the printed command once it is back.
1, 2Error or usageRead stderr; waiting will not fix it.

Every answer except a final one ends with Wait for what comes next: and the next command, carrying --since <seq>. Always run that command: an ask counts as new only after --since, so a loop sees each ask once and misses nothing, even across a daemon restart.

  • --until needs-you (default): gates, blocking escalations, blocks and the end.
  • --until final: only the end.
  • --until any-change: every ledger event, still answering 3 when an event opens an ask.

--json prints the same answer for machines, with next holding the next command. run follow streams a projection after each durable change until the run is final; run status reads it once. Interrupting any of them stops watching, not the run.

Read the status

StatusMeans
runningWork is under way.
waiting_humanAt least one human gate waits, even if other steps still run. Each waiting gate is in waitingGates with gateId and requestedSeq.
blockedStopped until someone resumes or aborts it. Never a delivery. Check resumeAllowed and resumePolicy.
succeededFinal: every path ended at a done End without a pick.
pickedFinal: the work reached a done End through a best-attempt pick. Failed work, retained.
failedFinal: a rejected End, a missing output, a fail Limit card or a coordinator failure. endedBy says who.
canceledFinal: aborted.

Runtime JSON is wrapped in .data; authoring JSON is not. Plain run status prints readable lines, including one output line per mission output.

Outputs and chaining

A succeeded or picked run lists its mission outputs: in run status, in the final run wait answer and in the cockpit. Chain a mission by passing a value on:

REPORT=$(archon --server "$ARCHON_SERVER" run status "$RUN" --json | jq -er '.data.outputs[] | select(.name == "report") | .value') archon --server "$ARCHON_SERVER" mission run next-mission --input spec="$REPORT" --json

A file or folder output's value is the path of the read-only copy Archon kept, under the run's artifact directory.

Attempts and evidence

Every attempt of every step, judges included, has its own directory, <state-dir>/.archon/artifacts/<run>/<node>/<attempt>/, where the seat writes selected evidence and Archon keeps output copies.

archon --server "$ARCHON_SERVER" run attempts "$RUN" # every step and attempt, verdicts and outputs archon --server "$ARCHON_SERVER" run attempts "$RUN" --node "$WORK" --files archon --server "$ARCHON_SERVER" run seats "$RUN" # seats, session names and what each waits on archon --server "$ARCHON_SERVER" run storage "$RUN" # evidence size and retention

In the cockpit, a step that ran shows N attempts; one click opens the attempts window, one column per attempt, oldest first: outcome, each gate's verdict and evidence, then what each output produced. Press C to compare two attempts side by side. The run bar's Produced list leads with what the run's final steps produced.

Run artifacts are temporary evidence with an ordinary budget of 32 MiB and 4,096 entries per run; history stays after files expire. Keep deliverables in the project. See Evidence and storage.

Stop a run

archon --server "$ARCHON_SERVER" run abort "$RUN" --reason "Wrong repository"

Abort cancels only that run and waits for its seats to be cleaned up before answering canceled. For blocked runs and restarts, see Recovery.

In the cockpit

  • Start mission (or ▶ on a step) opens one dialog asking for each input, the workspace, context paths and Bead.
  • The navigator lists every mission with its runs, by attention; a Needs you group counts every run waiting at a human gate or blocked, across all missions, and the page title carries the count.
  • The run bar names the run (Run 3), when it started, how long it took, who drives it, every gate that waits and every step that runs.
  • Clicking a seated step opens the seat's terminal. Type to the agent, select to copy, scroll.
  • /?mission=<slug>&run=<runId> links straight to a run; notifications carry these links.
