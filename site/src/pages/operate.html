Trust and network

No authentication, no authority checks

Whoever reaches the daemon, or runs the CLI against its state directory, can author missions, start, resume and abort runs, and answer gates. The daemon opens any file a mission references by absolute path, and seats run with full access as the daemon's user. This is deliberate (ADR-0021): safety lives in the configuration of the agents, the account they run as and the network perimeter.

  • Listen only on interfaces you trust. Repeat --listen for each one; the default is none, and the daemon refuses to start without one.
  • Reach a remote daemon through your own forwarding (an SSH tunnel, for example), not by listening on a public address.
  • The server URL a client uses must be an HTTP URL with a literal IP, without a trailing slash, credentials, query or fragment.
  • WebSocket terminal connections must come from the same origin as the request host.

Daemon flags

Every path flag takes an absolute path. With --executor tmux, --socket, --tmux-bin, --claude-transcripts and --codex-transcripts are required; --pi-transcripts is optional. The daemon sets no default working directory and no step time limit: runs name their own cwd or get a workspace, and only Limit cards limit.

The state directory

One daemon locks one state directory (coordinator.lock) and runs many missions concurrently within it. The same directory is the CLI's --workspace. Offline commands that execute, such as mission run or gate approve without --server, refuse while a daemon owns it: a daemon owns this state directory: run this through it with --server.

Keep it private (umask 077), outside any source checkout and outside the install prefix. Back it up as a whole; restart the daemon with the same directory and flags to keep missions and history. Layout: Where missions live.

The cockpit and its theme

  • An installed daemon finds ../share/archon/ui beside its bin directory. A source build needs --ui-dir pointing at a built dashboard/dist. --ui-dir '' turns the cockpit off.
  • GET /api/theme serves the bundled chrote-dark theme, or the schema-1 file named by --theme-file, read and validated on each request. A broken theme file answers 500 and leaves execution alone.
  • The cockpit's Style control chooses Console (the host theme) or Paper (a built-in light palette) for that browser only.

Needs-you notifications

--notify-command names an executable the daemon runs, with no shell and no arguments, for each needs-you event, writing one JSON notification on its stdin. Exit 0 means delivered; each send has 30 seconds. --cockpit-url is the base for links in messages. The command owns the channel, recipient and credentials.

KindSent when
human_gateA human gate asks. The body has the criterion, the input (up to 64 KiB), the cockpit link and the exact approve and reject commands.
escalationA blocking escalation is raised.
blockedThe run settles blocked with no escalation to explain it; resumable blocks include the resume command.
finalA run that finished while this daemon was running ends.

Each notification carries runId, missionSlug, missionTitle, kind, runStatus, gate and node identities, missionUrl, a one-line text and a complete plain-text subject and body. Each ask is sent once (recorded in the run's .needs-you.json), and failed sends are retried at the next settle, at startup and every five minutes. A placeholder command:

#!/bin/sh set -eu notification=$(cat) subject=$(printf '%s' "$notification" | jq -r '.subject') printf '%s' "$notification" | jq -r '.body' | "$NOTIFY_SENDER" --to "$NOTIFY_TO" --subject "$subject"

The daemon clears TMUX, TMUX_PANE and TMUX_TMPDIR from its own environment and sets TERM=xterm-256color, so starting it from inside tmux is safe. Seats do not inherit the daemon's environment: they take the tmux server's.

The CLI can also execute runs offline, without a daemon, when ARCHON_LAB_HARNESSES or ARCHON_TMUX_HARNESSES and the related ARCHON_TMUX_*, ARCHON_*_TRANSCRIPTS, ARCHON_STATE_DIR and ARCHON_AGENT_USER variables configure an executor. The test suite uses this path; for real work, run through the daemon.

Running under a supervisor

Archon ships no service files; supervision belongs to the host. What a supervisor must respect:

  • The tmux server outlives the daemon. Run it separately. A daemon shutdown detaches from working seats without ending them (left_shutdown) and the restarted daemon picks the run up again; killing the server loses those seats.
  • Stop with SIGTERM and allow about ten seconds. SIGTERM fences new work at once, gives active turns five seconds, and drains HTTP and execution within a ten-second budget. A watchdog is an outer limit, not the normal way to stop.
  • Restart with the same flags and state directory. Startup recovers interrupted runs before listening.
  • Give the daemon a PATH with the harness CLIs, and the tmux server the environment the seats need.

An illustration for systemd user units. Adapt every path; nothing here is installed for you.

[Unit] Description=tmux server for Archon seats [Service] Type=forking Environment=PATH=%h/.local/bin:/usr/local/bin:/usr/bin:/bin ExecStartPre=/bin/mkdir -p %h/.local/share/archon/state/tmux ExecStart=/usr/bin/tmux -S %h/.local/share/archon/state/tmux/seats.sock new-session -d -s archon-keep [Install] WantedBy=default.target [Unit] Description=Archon coordinator Wants=archon-tmux.service After=archon-tmux.service [Service] Environment=PATH=%h/.local/bin:/usr/local/bin:/usr/bin:/bin ExecStart=%h/.local/bin/archond --executor tmux \ --state-dir %h/.local/share/archon/state \ --listen 127.0.0.1:8091 \ --socket %h/.local/share/archon/state/tmux/seats.sock \ --tmux-bin /usr/bin/tmux \ --claude-transcripts %h/.claude/projects \ --codex-transcripts %h/.codex/sessions KillSignal=SIGTERM TimeoutStopSec=30 Restart=on-failure [Install] WantedBy=default.target

Before restarting a daemon with active work, read Restarting the daemon.
