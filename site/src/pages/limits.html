One card, one target

A Limit card covers one target: a step, or the Input card for the whole mission. A target has at most one card. A step covered by its own card and the mission's card stops at whichever is spent first.

Commands on this page are for bash or zsh and need jq. Take step, slot, gate and run IDs from the JSON a command returns (formation list "$M", run status "$RUN" --json); never guess one.

export ARCHON_SERVER=http://127.0.0.1:8091 # your daemon M=review # the mission slug WORK=fmn_... DRAFT=fmn_... # steps to cap LIMIT=lim_... # a Limit card ID from: archon --server "$ARCHON_SERVER" mission inspect "$M" RUN=run_... GATE=gate_... SEQ=... # a run blocked or waiting for a pick, from run status archon --server "$ARCHON_SERVER" limit create "$M" --target "$WORK" --rounds 3 archon --server "$ARCHON_SERVER" limit create "$M" --target input --rounds 20 --time 2h --warn 10m --title "Mission cap" archon --server "$ARCHON_SERVER" limit update "$M" "$LIMIT" --tokens 500000 --when-spent fail archon --server "$ARCHON_SERVER" limit update "$M" "$LIMIT" --time '' # an empty value clears a knob archon --server "$ARCHON_SERVER" limit delete "$M" "$LIMIT"

In the cockpit, drag the Limit block onto a step or the Input card. The card states its knobs in words (at most 3 rounds · 30 min) and has a dashed tether to its target; drag the tether's handle to rewire it.

The three knobs

Each knob is optional, and each one set is enforced.

--rounds

On a step: how many times it may run, send-backs and resumed re-runs included. On a peer step: how many journal messages its conversation may hold. On the Input card: how many step runs the whole mission may make, judges included. A start that a crash or shutdown cut short before its output is not a round.

--time (and --warn)

Wall time in whole seconds, written 45s, 30m or 1h30m. On a step it counts while an attempt runs: startup, work and finalization, but not waits on a human gate, blocks or daemon downtime, so a send-back resumes the step with the time it has left. On the Input card it counts while any step works. At the deadline the step's seats stop, keeping partial evidence. --warn 5m pastes one warning into the covered seats when that much time is left.

--tokens

What the covered seats spend, approximately and the same way for every harness: input not read from cache (cache writes included) plus all output, reasoning and subagents included. Seats are counted every two seconds, so a count can pass the budget by what was spent in between. Steps working at once share what the mission card has left.

When a card is spent

--when-spent says what happens. Before a step starts, the engine checks its own card, then the mission's, rounds before time before tokens.

ValueWhat happens
stop (default)The run blocks with limit_reached and a plain reason (Review used 3 of 3 rounds). It waits for a grant: run resume --grant gives one more round, or the card's time or tokens again.
failThe run fails at once with limit_reached, keeping every attempt's verdicts and outputs as evidence. Needs no one. Use it for missions meant to run unattended.
bestOnly on a step's card. The step's gate picks the best attempt it has judged, and that attempt goes on through the gate's pass route. See below.
archon --server "$ARCHON_SERVER" run resume "$RUN" --grant --reason "One more round; the reviewer's last points were small"

A plain resume at a spent limit is refused with 409. In the cockpit the run bar offers the grant in words: Grant one more round, or Grant 30 min more.

Best of N

Best of N is a step, its gate's fail route back to it, and a best card with N rounds. The step needs a selecting gate: exactly one judge or human gate that only this step feeds and whose fail route returns to it. A code-only gate cannot compare attempts.

archon --server "$ARCHON_SERVER" limit create "$M" --target "$DRAFT" --rounds 3 --when-spent best

When the card is spent, the candidates are the attempts the gate has judged. An attempt the limit cut short or a crash ended has no output and is never a candidate. With one candidate Archon takes it; with several, the gate decides:

  • A judge gate runs its chain once more on one input that shows every candidate side by side. Judges before the last recommend; the final judge answers with one archon-pick block.
  • A human gate asks the operator, with any judge's pick as a recommendation. Answer in the step's attempts window (Pick attempt N) or with gate pick.
```archon-pick {"attempt":2,"reason":"Why this attempt is the best","evidence":["what decided it"]} ``` archon --server "$ARCHON_SERVER" gate pick "$RUN" "$GATE" --attempt 2 --requested-seq "$SEQ" --reason "Tightest draft"

A picked run is not a success

A pick happens only when no attempt passed, so the picked attempt is failed work, retained. A run whose work reached its done End through a pick ends picked, not succeeded; run wait and run follow exit 7, and each output a pick carried names the pick and the verdict that failed it. Feed a picked output only into a mission that starts by repairing those findings. See ADR-0022.

Any run blocked at a spent step card whose gate has judged attempts also offers run resume --pick-best, whatever the card's whenSpent.

Rehearse it in lab

Give the input a failing verdict and a pick naming an attempt; the judge fails each round until the card is spent, then picks:

```archon-verdict {"verdict":"fail","reason":"Lab fixture","evidence":[]} ``` ```archon-pick {"attempt":2,"reason":"Lab fixture","evidence":[]} ```

Validation

Validation reports invalid_limit for a card wired to nothing, a second card on one target, a value that is not a positive whole number, a warning without time or not shorter than it, and a best card on the mission or on a step without a selecting gate. It warns empty_limit for a card that sets no knob. Full rules: CONTRACT.md, Limit cards and Picking the best attempt.
