Staff a slot with Pi

Commands on this page are for bash or zsh and need jq. Take step, slot, gate and run IDs from the JSON a command returns (formation list "$M", run status "$RUN" --json); never guess one.

export ARCHON_SERVER=http://127.0.0.1:8091 # your daemon M=review # the mission slug STEP=fmn_... # a step ID from: archon --server "$ARCHON_SERVER" formation list "$M" SLOT=... # a slot ID from: archon --server "$ARCHON_SERVER" formation inspect "$M" "$STEP" archon --server "$ARCHON_SERVER" formation assign "$M" "$STEP" --slot "$SLOT" \ --harness pi --model anthropic/claude-sonnet-5-5 --effort medium [[formation.slot]] id = "slot_draft" label = "Drafter" agentId = "builder" harness = "pi" model = "anthropic/claude-sonnet-5-5" effort = "medium"
Model

A provider/model name. The catalog offers anthropic/claude-opus-5-5, anthropic/claude-sonnet-5-5, anthropic/claude-haiku-5-5 and anthropic/claude-fable-5-1; a name from any other provider Pi knows works the same way, with that provider's credentials resolved by Pi. A blank model means Pi's own default.

Effort

Pi's thinking level, passed as --thinking: low, medium, high, xhigh or max, the same efforts as claude-code.

In the cockpit a Pi slot reads Pi · anthropic/claude-sonnet-5-5 · medium on the card and Drafter is builder on Pi · anthropic/claude-sonnet-5-5 · medium in its window.

How a Pi seat starts

The daemon resolves pi on its own PATH and launches, in a fresh tmux session:

exec /path/to/pi --model --thinking --approve --session-dir /
  • --approve trusts the folder's project files for this launch only: no trust dialog, and nothing written to Pi's trust.json. Pi asks no tool permissions, so the seat has full access.
  • --session-dir keeps the seat's saved session in Pi's own per-folder layout under the transcript root, whatever Pi's settings say, so pi --resume in the seat's folder finds it.
  • Archon never puts a key on a command line.

Credentials

A seat takes its environment from the tmux server, not from the daemon. A Pi seat's key therefore lives either in Pi's own auth file (sign in with Pi as the daemon's user) or in the tmux server's environment. Changing the server's environment means restarting that server; see Start a tmux server.

Transcripts and completion

Archon reads Pi's session files to know when a turn finished. archond --pi-transcripts names the root; without it the daemon uses $PI_CODING_AGENT_DIR/sessions, else ~/.pi/agent/sessions, from its own environment. A dispatch completes on Pi's assistant message with stopReason stop that carries this run's completion sentinel, in the seat's session, with the slot's model.

Token counting

For a Limit card's --tokens, a Pi dispatch counts input + cacheWrite + output of each assistant message after its brief pointer. That matches how Claude Code and Codex are counted: input the model did not read from its cache, plus every output token.

Pi as the managing agent

Pi can also be the agent that drives Archon. Link the archon skill into ~/.agents/skills, where Pi discovers user-level skills (Let agents drive), and Pi authors missions, runs them with run wait and answers gates with you like any other managing agent.
