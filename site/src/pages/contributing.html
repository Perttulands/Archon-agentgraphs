The rules

AGENTS.md holds three rules for every change, with reasons in PRODUCT.md:

  • Add no sandboxing, file confinement, blast-radius limits or authority checks.
  • Land renames and reshapes whole: migrate live data once, delete the old path, and add no deprecated aliases or compatibility shims.
  • Put no eval harness, tests or CI around the archon skill.

Product direction (scope, the trust or visibility model, supported formation types, UX direction) is not settled inside a change; it is raised as a decision Bead labelled product-decision. Platform shortcomings found during work are recorded as Beads labelled platform-gap.

Work on this site

The site lives in site/ and needs only Node 20.19 or newer: no dependencies to install.

node site/build.mjs # writes site/dist and checks every link python3 -m http.server --directory site/dist 8000 # preview at http://127.0.0.1:8000
  • Pages are HTML fragments in site/src/pages/; the navigation is site/site.config.mjs.
  • repo:path#anchor links point into the repository and are checked against the files and their headings.
  • The CLI and daemon references are generated from the binaries: node site/tools/gen-reference.mjs --bin <dir-with-archon-and-archond>, or --check to fail when they are stale.
  • Code blocks marked validate="mission" are validated by archon mission validate when the build is given --archon <path-to-archon>.

CI's docs-site job runs the reference check and the build with --archon on every push.

Release packaging, tagging and publishing are described in docs/releasing.md.
