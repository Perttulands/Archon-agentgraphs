Same number, different software

The repository's VERSION file has not been bumped since {{release.tag}}, so a release archive built from today's source is also named archon-{{version}}-linux-<arch>.tar.gz. Until a new release is cut, the commit is the only reliable identity.

What changed since {{release.tag}}

Archon lands renames whole, with no compatibility layer. The current source therefore refuses many things {{release.tag}} accepted. The main differences:

Area{{release.tag}}Current source
Reusable unitBoard, .formations/boards/*.formation.toml, archon board …Mission, .archon/missions/*.mission.toml, archon mission …
Entry nodeMission node on a boardInput card with declared inputs and outputs
Commandsarchon, archond and a formationsd compatibility commandarchon and archond only
HTTP/api/formations/* still answered/api/missions, /api/runs; the old routes are gone
Run inputs--mission and --brief on mission runNamed inputs: --input name=value, --input-file name=path
LimitsLaunch flags such as --max-dispatch, --max-attempts, --wall-clock-secondsOnly Limit cards on the mission; a launch sets none
Ending pathsNo End nodesEnd nodes (done, rejected); every route must lead somewhere

HarnessesClaude Code and CodexClaude Code, Codex and Pi
StaffingPersonas chose the harnessEach slot states its harness, model and effort; roles are text only
CockpitBoard editor and terminal PeekFloating node windows, seat terminals, attempts, best-attempt picks, Flow view

The draft notes for the next release are in docs/release-notes.md. The release workflow publishes that file as the release body.

Moving from {{release.tag}} state

There is no migration command in the CLI. State from {{release.tag}} lives under <state-dir>/.formations/; current Archon reads only <state-dir>/.archon/. The release notes describe the cut-over as a one-time migration a deployment performs with archond stopped; that tooling lives with the host deployment, outside this repository. For a personal setup, the simplest path is a fresh state directory: copy the current examples in and rebuild your missions with the current commands.
